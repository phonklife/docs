The Suno API surface is split into task-oriented endpoints for music generation, retrieval, lyrics, stems, and agent integrations.

## Base URL

Replace `http://localhost:3000` with your deployed Suno API URL when calling these endpoints remotely.

## Authentication

Suno API authenticates with the browser session cookie from your Suno account. Configure `SUNO_COOKIE` on the server, then optionally override it per request with a `Cookie` header on endpoints that support account rotation.

<Note>
  See [Authentication](/configuration/authentication) for the full cookie flow, required fields, and refresh behavior.
</Note>

## Common request patterns

### Generate now, poll later

Most music-creation endpoints return immediately when `wait_audio` is `false`. In that mode, Suno API gives you clip IDs first and you poll [`GET /api/get`](/api-reference/get) until the returned clip status becomes `streaming` or `complete`.

### Block until audio is ready

When an endpoint supports `wait_audio`, set it to `true` to make the server poll Suno on your behalf for a short window before returning.

### Per-request account override

Most endpoints use the server's default `SUNO_COOKIE`. Endpoint-specific notes call out when you can pass a request `Cookie` header to use a different Suno account.

## Common response patterns

- `/api/generate` and `/api/custom_generate` return **two clips** per request
- Retrieval endpoints usually return normalized clip metadata such as `id`, `title`, `audio_url`, `image_url`, `status`, and `model_name`
- Some endpoints, such as `/api/clip`, return raw Suno payloads instead of normalized wrapper fields

## Common error patterns

| Status | Meaning |
|---|---|
| `400` | Missing or invalid request data |
| `402` | The authenticated Suno account has no usable credits |
| `500` | Suno API or upstream Suno request failed |
| `503` | Temporary network or upstream availability failure |
